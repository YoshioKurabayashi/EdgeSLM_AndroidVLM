| | |
|---|---|

## 1. 目的

StudyMemo の各章は「何を学んだか」を書いている。この道具は、それを**実際のソースと結果**に結びつける:

- **地図の章**（ソースと動かし方）: 節ごとに、どのファイルのどの関数（何行目）がやっているか・どのコマンドで確かめるか・結果はどのファイルか
- **コードの章**（コードで読む検証）: 検証ごとに、道具・コマンド・流れ・**実際のソースの抜き出し（行番号つき）**・1 行ずつの解説・結果の値
- **演習**（`ex*.py`）: スマホも GPU も要らず、数秒で数字の意味を手で確かめる

## 2. 構成

| ファイル | 役割 |
|---|---|
| `make_code_tour.py` | `tour/*.md`（テンプレート）を読み、印をソース・結果から置き換えて `DoC/StudyMemo/` の章を書く |
| `tour/*.md` | 章の解説だけを書いたテンプレート。1 行目の `<<OUT …>>` が出力先 |
| `_src.py` | 演習用。本物のソースファイルから**関数・定数の定義だけ**を取り出して実行する（重い import をせずに本物の式を使う） |
| `ex*.py` | 演習（下の表） |
| `__init__.py` | `python -m app.study.<名前>` で動かすため（空） |

## 3. なぜ「生成」にしたか

抜き出しを手で写すと、ソースを直したときに行番号・中身がずれ、**気づかないまま古い説明が残る**。
テンプレートには解説だけを書き、抜き出し・行番号・結果の値は毎回ソースから取る。
抜き出しの始まりの目印（正規表現）がソースに**ちょうど 1 か所**見つからなければ止まるので、ずれたら必ず気づける。

## 4. テンプレートの印

| 印 | 置き換わるもの |
|---|---|
| `<<OUT パス>>`（1 行目） | 出力先（プロジェクトからの相対パス） |
| `<<CODE パス \| 始まり \| 終わり [\| from=目印] [\| omit=A..B]>>` | 始まり〜終わりの行を行番号つきで。`終わり` は正規表現か `+N`（N 行）。`omit=A..B` は A の次〜B の手前を「中略」に |
| `<<DIFF 元 \| 新>>` | 2 つのファイルの差分 |
| `<<JSON パス \| 式>>` | JSON を `d` として読んだ式の値（整形） |
| `<<L パス \| 正規表現>>`（文中） | その行の番号「L123」 |
| `<<VAL パス \| 式>>`（文中） | JSON の式の値（1 行） |
| `<<MD5_TABLE>>` | この章で使ったファイルの行数と md5 |

区切りは「空白 + `|` + 空白」。正規表現の中の `|`（空白なし）はそのまま使える。テンプレートの中の ``` の囲みでは印を置き換えない。

## 5. 演習が本物のソースを使う仕組み（`_src.py`）

道具のファイルは先頭で onnx などを import するので、そのまま import するとそれらが要る。`_src.load(パス, [名前…])` は
ファイルを構文木として読み、指定した名前の関数・クラス・定数の定義だけを numpy と一緒に実行する（型注釈は評価しない）。
**書き写さないので、ソースを直せば演習もそのまま追従し、写し間違いが起きない。** 名前が見つからなければ止まる。

## 6. 使い方

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
cd <プロジェクトのフォルダ>
& <venv の python> -B -m app.study.make_code_tour --check    # 目印が全部見つかるかだけ（書かない）
& <venv の python> -B -m app.study.make_code_tour            # 章を書き直す
& <venv の python> -B -m app.study.ex01_…                     # 演習
```

`-B` は `__pycache__` を作らないため（ソースのフォルダを汚さない）。

## 7. 確かめたこと

- 作成時に、端末の VM（Python 3.10・numpy）で `make_code_tour --check`・生成・全部の演習を流して通ることを確かめた
- 生成した章に未解決の印（`<<`）が残っていないこと

## 8. 直すとき

- ソースを直した → `make_code_tour` を流す。止まったら、その目印をテンプレートで直す
- 解説を直したい → `tour/*.md` を直して流す（生成された `DoC/StudyMemo/` の章を直接直さない。次の生成で消える）
- 演習を足す → `ex0N_….py` を足し、地図の章の演習の表と、この README の表に足す

## 10. 学習の章の中にソースを載せる（`sync_src.py`、2026-10-17）

利用者の依頼「StudyMemo の解説と、該当する箇所のソースがどうなっているかを並べて学習できるようにしたい」で足した道具。
地図の章・コードの章（`make_code_tour.py` が丸ごと作る）とは別に、**手書きの学習の章の各節の終わり**に、その節で解説している処理の実際のソースを置く。

| 項目 | 内容 |
|---|---|
| 枠 | `<!-- src: パス \| 始まり \| 終わり [\| from=…] [\| omit=A..B] [\| note=一言] -->` 〜 `<!-- /src -->`。枠の**中だけ**を `sync_src.py` がソースから書き直す（行番号つき・md5 つき）。枠の外の解説と「目印 \| 何をしているか・なぜ」の表は手書き |
| ソースが無い節 | `<!-- src: なし \| 理由 -->` 〜 `<!-- /src -->`（考え方の説明・まとめ・端末の外の測定など）。理由がそのまま「**ソース**: なし — 理由」と表示される |
| 一覧 | 目次（StudyMemo.md）の `<!-- srcindex -->` 〜 `<!-- /srcindex -->` に、章・節ごとの枠の一覧を自動で書く。枠も「なし」も無い節は「（未記入）」 |
| ずれの検出 | 始まりの目印がソースに**ちょうど 1 か所**でなければ止まる。`--check` は書かずに、解決できない印・古くなった枠・未記入の節を出す |
| 書き方の決まり | 抜き出しは 1 枠 40 行くらいまで（長い所は `omit=`）。表の各行は、枠の中に実際にある文字列を「目印」にする（ソースが変わって目印が消えたら、表も直す合図） |

```powershell
& <venv の python> -B -m app.study.sync_src --check     # 古い枠・解けない印・未記入の節を確かめる（書かない）
& <venv の python> -B -m app.study.sync_src             # 枠を全部ソースから書き直す
& <venv の python> -B -m app.study.sync_src DoC/StudyMemo/03_xx.md   # その章だけ（目次の一覧は書き直さない）
```

ソースを直したら `make_code_tour` と `sync_src` の両方を流す。どちらも標準ライブラリだけで動く。
