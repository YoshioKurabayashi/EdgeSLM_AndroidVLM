### 2.1 壊れ方の特徴（SRQ なしの版）

| 見たもの | 端末 | PC の QDQ |
|---|---|---|
| 画像 0 と他の画像の出力の cos | **0.998〜0.999** | 0.19〜0.25 |
| トークン 0 と他のトークンの cos | **0.997〜1.000** | 0.09〜0.73 |
| 1 トークンの大きさ（ノルム） | 40.5 前後で一定 | 16〜22 でばらつく |
| 値の分布（並べ替えて比べた cos） | 0.997（形は似ている） | — |

- **入力の並べ方の取り違えではない**: 全部 0・全部 0.5・全部 1・転置・チャネル先頭の並べ方の入力を PC の QDQ に通しても、端末の出力には似ない（cos 0.02〜0.07）
- 射影層の重みから、端末の出力を「射影層の入力（正規化した後）」に戻してみた（PC の QDQ で同じことをすると HF と cos 0.9998 で戻る）。
  端末では**どの画像・どのトークンも同じベクトル**で、巨大な活性のチャネル（175・650）が大きい。層 15 の出力の全体平均とは cos 0.25 で、
  「プーリングが全部を平均してしまった」だけでは説明できない
- まとめ: **途中のどこかで、画像とトークンごとの情報が消え、同じ値に潰れている**。潰れる場所の候補:
  - 630 トークンの 4 次元のテンソル（attention の [1,630,12,64]・プーリングの [21,10,3,768]）の扱い。文章側はトークン 1 つなので、
    軸の取り違えがあっても長さ 1 の軸で隠れていた可能性がある
  - 層 5 から現れる巨大な活性（最大 2,158）と 16bit の計算（RMSNorm の x² など。EdgeSLM_Android の C-11 と似た型）
  - 630 の長さの softmax（EdgeSLM_Android で「窓が長いほど端末だけの誤差が増える」記録がある）

## 7. 切り分けの結果（2026-09-29 09:13〜10:34、`probe_vit`）

### 7.1 途中の値ごとの「端末 ↔ PC の QDQ」（4 枚の中央値）

2 層版（変換 89 秒、1 枚 25ms）と 16 層版（変換 56 分、1 枚 167ms）。どちらも strict=true。2 層版の値は 16 層版と同じだった。

| 途中の値 | 端末 ↔ QDQ 相対 L2 | cos | （参考）QDQ ↔ float | トークンの似かた 端末 / QDQ | max\|x\| 端末 / QDQ |
|---|---:|---:|---:|---|---|
| **パッチの埋め込み** | **21.8** | 0.047 | 0.003 | **0.999** / 0.577 | 68.5 / 68.4 |
| 層 0 | 13.2 | 0.044 | 0.008 | 0.999 / 0.815 | 78.6 / 99.1 |
| 層 1 | 9.9 | 0.085 | 0.007 | 0.999 / 0.886 | 82.2 / 148.9 |
| 層 5 | 2.1 | 0.268 | 0.002 | 0.999 / 0.990 | 219 / 558 |
| 層 15 | 1.6 | 0.185 | 0.035 | 0.999 / 0.797 | 507 / 2,070 |
| プーリング後 | 1.8 | 0.218 | 0.021 | 0.999 / 0.890 | 502 / 1,741 |
| 最終出力 | 2.2 | 0.048 | 0.043 | 1.000 / 0.509 | 3.5 / 3.4 |

**最初の段（パッチの埋め込み＝入力 × 重み ＋ 位置）で既に壊れている**。層や softmax や巨大な活性が原因ではなかった。

### 7.2 パッチの埋め込みの壊れ方

- 端末の値のうち **29% が出力の範囲の端（±68.45）に張り付いている**（QDQ では 0.07%）。張り付いた値の符号は本当の値の符号と無関係（一致 51%）
- 張り付くかどうかは**チャネルで決まる**: 768 チャネルのうち 222 本はほぼ全トークンで張り付き（9 割超）、545 本はほぼ張り付かない。
  **張り付かないチャネルは PC の QDQ とぴったり一致**（倍率の中央値 1.000、相関の中央値 1.000）
- **張り付くチャネル ＝ 重みのスケールが小さいチャネル**。壊れた 222 本は全部 s < 3.995e-6、正常な 546 本は全部 s ≥ 4.085e-6。境目がきれいに分かれた

| | 重みのスケール s（出力チャネルごと） | そのチャネルの重みの大きさ max\|w\| |
|---|---|---|
| 壊れたチャネル（222 本） | 1.7e-10 〜 4.0e-6 | 2e-8 〜 5e-4（ほぼ 0） |
| 正常なチャネル（546 本） | 4.1e-6 〜 2.7e-3 | 5e-4 〜 0.34（中央値 0.032） |

- パッチの埋め込み（input_proj）は QAT ではない float の重みで、2-2 で「max|w|/127 をスケールにして INT8 に」作り直したもの。
  **重みがほぼ 0 のチャネルが 222 本ある**（学習で使われなくなったチャネルとみられる）ので、スケールも極端に小さくなった
- NPU は行列積の結果を「入力のスケール × 重みのスケール ÷ 出力のスケール」の倍率で 16bit に直す。この倍率を固定小数点で持つので、
  **小さすぎると表せず、でたらめな値が出て範囲の端に張り付く**とみられる（境目は最大のチャネルの 1/659）。PC の ORT は float で計算するので壊れない
- 本当の値はほぼ 0（そのチャネルの出力は最大 0.7、ほかは 68）。壊れた値 ±68 が**どのトークンでも同じチャネルに同じ符号で**入るので、
  後ろの層ではそれが支配して、全部のトークンが同じ値に潰れて見えた（6 節までの「画像にもトークンにも依存しない」の正体）
- 同じ作り方の射影層（768→1536）は最小のスケール 5.6e-4 で該当しない。QAT の 112 本は最小 2.2e-4（最小/最大 0.09 以上）で該当しない

### 7.3 直し方（C-14、本プロジェクトで新設）

`qat_inject_vit._from_float` で、**出力チャネルごとのスケールに下限（そのテンソルの最大のスケールの 1/64）**を付ける（境目 1/659 に対して 10 倍の余裕）。

| | 下限なし | 下限あり |
|---|---:|---:|
| 下限に上げたチャネル | — | 309 本（壊れた 222 本を含む） |
| 重みの相対 L2 | 0.9807% | 0.9810% |
| パッチの埋め込みの出力の相対 L2（float との比較、画像 0） | 0.2663% | 0.2684% |

精度はほとんど変わらない（該当チャネルの重みはほぼ 0 なので、整数が 0〜十数になるだけ）。
あわせて quantize_vit に「重みのスケールの最小/最大が 1/64 以上か」の検査（C-14）を足した。

- **端末の特徴でも答えの品質は保たれた**（45/123。基準 42、量子化前の自前 45）。基準との入れ替わりは上下ほぼ同数
- PC の QDQ（49）より 4 問少なく、入れ替わりは 0↑・4↓。偏って見えるが、4 問だけでは偶然と区別できない（4 問とも同じ向きになる確率は 1/8）。
  自前の float（45）とは 3↑・3↓で同じ。PC の QDQ の 49 は、これまでの 70 トークンの結果（42〜49）の中で一番高く、揺れの上の端とみられる
- 端末だけの誤差 7% は、答えの品質を変えなかった（2-1 の「特徴が 1〜3 割変わっても品質は同じ」と整合）
