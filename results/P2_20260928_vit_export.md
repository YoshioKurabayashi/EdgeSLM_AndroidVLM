## 1. 結論

| 問い | 結果 |
|---|---|
| Q7 自前の配線は HF と同じ計算か | **同じ。** SRQ なしで出力の相対 L2 最大 1.1e-5・平均 1.2e-6、cos 0.999999999998。途中の値は層ごとに滑らかに増える（下の表）＝足し算の順序の差だけ |
| ×√768 を省く書き換え | **同じ計算**（省いた形と省かない形の差 3.5e-7） |
| ONNX に書き出せるか | **書き出せた。** 1,600 ノード・587MiB、演算は想定の 15 種だけ（Expand・Gather・Cast なし）、形はすべて固定、入力を最初に使うのは Sub、行列積は 重み 114・活性×活性 32（想定どおり） |
| ONNX（ORT CPU）は自前と同じか | **同じ**（cos 0.99999999993、相対 L2 最大 1.1e-4）。初回の目安 1e-4 をわずかに超えて「不合格」と出たが、目安の置き方の問題（2.3 節）。目安を見直した |

## 2. 配線の確認

### 2.1 自前 ↔ HF（SRQ なし）の途中の値（2 枚、相対 L2 の最大）

| 位置 | vg_00 | vg_13 |
|---|---:|---:|
| パッチの埋め込み（位置の埋め込みを足した後） | **0**（完全一致） | 0 |
| 層 0 | 2.9e-7 | 2.8e-7 |
| 層 5 | 2.1e-7 | 2.5e-7 |
| 層 10 | 1.7e-6 | 8.4e-7 |
| 層 15 | 2.1e-5 | 7.0e-6 |
| プーリングの後（×√768 の尺度） | 2.3e-6 | 1.6e-6 |
| **出力（16 枚の最大）** | **1.1e-5** | |

パッチの埋め込みが 0 なのは、位置の埋め込みを定数にしても値が 1 ビットも変わらないことを示す。層を追って 1e-7 → 1e-5 と滑らかに増えるのは
足し算の順序の差（HF の attention は SDPA、自前は行列積）。配線の誤りなら、ある層で急に 1e-2 以上に跳ぶ。

### 2.2 書き出した ONNX

| 項目 | 値 |
|---|---|
| ノード | 1,600（Mul 403・Add 209・MatMul 146・Slice 128・ReduceMean 115・Pow/Sqrt/Reciprocal 各 113・Reshape 67・Neg 64・Transpose 64・Concat 32・Softmax 16・Tanh 16・Sub 1） |
| 大きさ | 587MiB（`.onnx` 1.7MB ＋ 外部データ 614MB） |
| 入出力 | `pixel_values` [1,630,768] → `image_embeds` [1,70,1536]（固定） |
| 行列積 | 右辺が重み 114（16 層 × 7 ＋ パッチの埋め込み ＋ 射影層）、活性×活性 32（16 層 × 2。C-8 で右辺を 8bit に落とす対象） |
| RMSNorm | Pow 113 本 ＝ 16 層 ×（4 ＋ q/k/v_norm 3）＋ 射影層 1 |
| 較正データ | 64 枚 → `work/ops/vit_b70_21x30/vit_b70_21x30_calib.npz` |

### 2.3 ORT CPU との比較と、目安の見直し

ORT CPU ↔ 自前: 相対 L2 最大 1.1e-4、cos 最小 0.99999999993。ORT ↔ HF も同程度（最大 1.08e-4）。

cos が小数点以下 10 桁まで一致しているので、書き出しで計算が変わったのではない。ORT の CPU 実装（行列積の足し算の順序、tanh などの近似）との差が、
最後の層の大きな値（最大 2,158）で相対的に目立ったものとみられる。目安を「cos ≥ 0.999999 かつ 相対 L2 の最大 ≤ 1e-3」に改めた
（書き出しの誤りなら cos が桁で落ちる）。この後の量子化の誤差（% の桁）に比べれば無視できる。ORT CPU で 1 枚 0.76 秒（参考）。

## 3. SRQ（QAT の 8bit の丸め）への敏感さ ★

### 3.1 HF どうしでも、SRQ のあり・なしで特徴が大きく変わる

| 位置 | HF の SRQ あり ↔ なし（相対 L2 の平均、2 枚） |
|---|---|
| パッチの埋め込み | 0（SRQ が掛からない。QAT ではない float の層） |
| 層 0 | 0.13 / 0.26 |
| 層 5 | 0.09 / 0.09 |
| 層 10 | 0.15 / 0.15 |
| 層 15 | 0.43 / 0.55 |
| 出力（16 枚） | 平均 0.52（画像ごとに 0.38〜0.70）、cos 0.86 |

層 0 で既に 1〜2 割変わる。QAT の活性の目盛り（スケール 0.015〜0.71）は粗く、8bit に丸めるだけで値が大きく動く。
この QAT 版は SRQ を掛けた状態で学習しているので、**SRQ ありが本来のモデル**（Phase 1 の品質の評価もこちら）。

### 3.2 自前（SRQ あり）↔ HF（SRQ あり）も大きく離れる

| | 相対 L2 の平均 | 最大 | cos 最小 |
|---|---:|---:|---:|
| 自前 ↔ HF（SRQ なし） | 1.2e-6 | 1.1e-5 | 0.999999999998 |
| **自前 ↔ HF（SRQ あり）** | **0.32** | 1.44 | **0.84** |
| （参考）HF の SRQ あり ↔ なし | 0.52 | 1.77 | 0.86 |

SRQ なしでは 1e-5 で一致するので、配線は同じ。SRQ ありでは、計算の順序の差（1e-7）が 8bit の境目にかかると 1 目盛り（スケールによっては 0.3 以上）転び、
それが 16 層で広がる。Phase 1 の文章側（1 位の一致 77〜89%）と同じ現象だが、**画像エンコーダの方がずっと強く出る**。
（層ごとの差は 6.1 節で確かめた: 層 0 では 6e-5 と小さく、層を追って増える＝揺れ。SRQ の掛け方の誤りではない）

### 3.3 意味

- **端末の特徴も、HF とは cos 0.85 前後までずれうる。** 端末は計算の順序も量子化も違うので、同じ揺れが起きる
- したがって「端末の特徴と HF の特徴の cos ≥ 0.99」は**正しく作っても届かない**。基本設計の合格の目安（Q8・Q10）を改める:
  - 算術の誤差は **SRQ なしの版**（qat_inject の `--no-srq`）で見る。揺れが無いので、量子化と NPU の誤差だけが見える
  - SRQ ありの版は**答えの品質**で判定する（Phase 1 の「全体の点と入れ替わりの偏り」）
- その前提として、**「特徴が 1〜3 割変わっても答えの品質は保たれるか」を PC で先に確かめる**:
  自前の配線（SRQ あり・なし）の特徴を文章側に入れて 126 問を解く（`ref_vlm --vision own / own_nosrq`）

## 4. 値の範囲（残差＝各層の出力、評価用 16 枚）

| 位置 | max\|x\|（SRQ あり） | RMS | 99.9% 点 |
|---|---:|---:|---:|
| パッチの埋め込み | 68 | 1.7 | 65 |
| 層 0 | 87 | 2.9 | 66 |
| 層 4 | 271 | 7.9 | 158 |
| 層 5 | **521** | **17.1** | 405 |
| 層 10 | 917 | 30.0 | 748 |
| 層 15 | **2,158** | **53.5** | 898 |
| 出力（射影層の後） | 3.8 | 0.56 | 2.2 |

- 残差は層を追って大きくなり、**層 5 で急に 2 倍**になる（巨大な活性が生まれる層）。最大は RMS の 30〜40 倍
- 16bit（65,536 段）なら、層 15 でも 1 目盛り ≒ 4,316 / 65,535 ≒ 0.066。RMS 53 に対して 0.12% なので、**残差の 16bit は持つ見込み**
- 8bit なら 1 目盛り 17 で無理だが、SRQ（8bit）が掛かるのは Linear の入出力（正規化の後）で、残差そのものには掛からない
- 出力（射影層の後）は小さい（Phase 1 と同じ）。文章側の入口の目盛りにも収まる（Phase 1 で確認済み）

## 6. 追加の確認（2026-09-28 実行）

### 6.1 SRQ ありの途中の値（自前 ↔ HF、相対 L2 の平均）

| 位置 | vg_00 | vg_13 |
|---|---:|---:|
| パッチの埋め込み | 0 | 0 |
| 層 0 | **6e-5** | **4e-5** |
| 層 1 | 0.013 | 0.006 |
| 層 2 | 0.059 | 0.033 |
| 層 5 | 0.047 | 0.042 |
| 層 10 | 0.099 | 0.100 |
| 層 15 | 0.32 | 0.43 |

層 0 では 6e-5（SRQ なしの 3e-7 より大きいが、まだ 1 万分の 1 以下）。層 1〜2 で 1〜6% に跳ね、あとは層を追って増える。
**SRQ の掛け方の誤りなら層 0 で既に大きい**ので、これは「境目で転ぶ」揺れ。配線は正しい。

### 6.2 自前の特徴で 126 問を解く（固定の格子・70 トークン）

| 画像エンコーダ | HF の特徴との cos（最小 / 中央値） | 答えが基準と完全に同じ | ×→○ | ○→× | 点 |
|---|---|---:|---:|---:|---|
| HF（基準） | 1 | — | — | — | 42/123（0.35） |
| **自前・SRQ あり** | **0.838 / 0.924** | 24/126 | 9 | 5 | **46/123（0.39）** |
| 自前・SRQ なし | 0.703 / 0.840 | 26/126 | 8 | 5 | 45/123（0.38） |

- **特徴が cos 0.84〜0.92 ほどずれても、答えの品質は保たれる**（むしろ誤差の範囲で同等〜少し上）。答えの文は 8 割が変わるが、正しさは変わらない
- **SRQ なし（cos 中央値 0.84）でも品質は同じ。** 文章側は画像の特徴の細かな違いに敏感ではない
- 入れ替わりは 9↑・5↓ と 8↑・5↓。偏りがあるように見えるが、問題数（126）と判定の揺れを考えると有意ではない（符号検定で p≈0.4）

### 6.3 意味（Phase 2 の進め方）

1. **端末の特徴が HF と cos 0.85 前後ずれても、答えの品質は保たれる見込み。** 2-2 以降は予定どおり「答えの品質」で判定する
2. **SRQ を端末で再現しなくても品質は落ちない見込み。** 2-2 では SRQ あり・なしの 2 版を作り、変換のしやすさ・速さ・品質で選ぶ
   （SRQ ありは行列積の入力が 8bit になるので、NPU では速くなる可能性がある）
3. 2-1 はこれで完了。**2-2（量子化）へ進む**
